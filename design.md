## 1.1 Text styles — all 15

Every style is **Inter Tight, weight 400, letter-spacing 0px** except the two
explicitly-named legacy Inter styles.

Framer exports three tiers per style: a `base` (declared `minWidth: 0`) plus
overrides at `minWidth: 1200` and `minWidth: 768`. Note the base carries the
*largest* value and the numbered tiers get progressively smaller, so the
`minWidth` labels do not read as normal CSS min-width. Interpreted below as
descending viewport bands — see Conflict **C-9**.

## 3.9 Typography rules

**🔠 Font rules** — Inter Tight ONLY, no exceptions · Mono for code, tokens, `kbd`,
`pre` · Variable font 100–900 · `@import` from Google Fonts already in CSS.

**✅ Always** — use `var(--ts-*-size)` · use `var(--fluid-*)` for viewport-scaled
text · use `var(--font-weight-*)` for weight · set `lineHeight` via
`var(--core-line-height-*)`.

**❌ Never** — hardcode `16px`, `24px`, `#fff` in components · use Tailwind
font-size classes (`text-2xl`) · use Tailwind font-weight classes (`font-bold`) ·
set px values on `font-size` directly.

**♿ Accessibility** — min 16px body text (`--ts-body-md-size`) · min 4.5:1 contrast
for body (WCAG AA) · min 3:1 for large text (18px+) · never disable user font
scaling (no max-size).

## 3.12 Design guidelines

**Principles** — **Consistency:** use design tokens and components consistently to
create a unified experience; consistent patterns help users learn faster.
**Clarity:** clear visual hierarchy, readable typography, intuitive layouts; every
element should have a clear purpose. **Accessibility:** design for all users
regardless of ability; follow WCAG, ensure contrast, support keyboard and screen
readers. **Efficiency:** help users accomplish tasks quickly with minimal friction;
reduce cognitive load.

**8-point grid** — creates mathematical harmony and ensures elements align across
screen sizes. All spacing should be multiples of 8px: 8, 16, 24, 32, 40, 48, 64.
✅ Do `margin: 16px`, `padding: 24px`, `gap: 32px`. ❌ Don't `margin: 13px`,
`padding: 27px`, `gap: 35px`.

**Container widths** — Small 640px · Medium 768px · Large 1024px · Extra Large 1280px.

**Responsive breakpoints** — Mobile 0–640px · Tablet 640–1024px · Desktop
1024–1280px · Wide 1280px+.

**Colour usage** — ✅ use accent sparingly for important actions and highlights ·
ensure 4.5:1 minimum contrast · use destructive colour only for delete/remove ·
test with colourblind simulators. ❌ avoid too many colours in one interface ·
don't rely on colour alone to convey information · never use accent for large
backgrounds · avoid pure black on pure white.

**Typography practice** — *Hierarchy:* use h1–h4 for structure · maintain clear size
differentiation · limit to 3–4 heading levels per page · one h1 per page.
*Readability:* line length 50–75 characters · line height 1.5 for body ·
paragraph spacing 1em · sentence case for UI labels.

**Iconography** — use familiar icons (home, search, settings) · pair with labels,
especially for less common actions · consistent sizing at 16/20/24px · always
provide `aria-label` or alt text for icon-only buttons.

**Motion** — *Duration:* micro-interactions 100–200ms · small elements 200–300ms ·
medium 300–400ms · large 400–500ms. *Easing:* entering `ease-out` · exiting
`ease-in` · moving `ease-in-out` · default `cubic-bezier`. Always respect
`prefers-reduced-motion`; those users should see minimal or no animation.

### C-9 — Framer breakpoint tiers read backwards *(interpretation applied)*

**Interpretation applied here:** these are descending viewport bands —
`base` = ≥1440, then 1200–1439, then 768–1199, with <768 inheriting the 768 value.
**Evidence:** Display resolves to 80/64/48, which matches both the saved-CSS preset

**Confidence: high**, but it is an inference about Framer's export format, not a

**Status:** unresolved, needs a fix in Framer.
