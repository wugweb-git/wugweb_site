# Eval 7: cover rule

Prompt: Is this cover on brand? A laptop on a desk showing a generic analytics dashboard, for our fintech case study.

Files read: `SKILL.md`, `references/standing-rules.md`, `references/review-gates.md`, `references/visual-os/judging-a-visual.md`, `references/visual-os/art-direction.md`, `references/visual-os/formats-and-campaigns.md`, `references/visual-os/metaphors.md`, `references/visual-os/objects-and-components.md`

## Response

Mode: Visual check, on a written description only. No image was supplied, so the cover itself was not seen.

**Result: fail. No, it is not on brand.**

**Overall impression.** This is the one cover the brand names as never allowed. A laptop with a generic dashboard could front any fintech project by any studio, so it says nothing about this client or what changed for them.

**What the description says**

| Part | As written |
| --- | --- |
| Subject | A laptop showing a generic analytics dashboard |
| Composition | A laptop on a desk |
| Lighting, colour, style, mood | Not stated |

**Mode.** A case-study cover is editorial or product proof (`references/visual-os/formats-and-campaigns.md`). This meets neither: product proof needs one credible, real module, "never a canvas of fake analytics widgets".

**Findings**

| No. | What | Rule and file | Severity | Fix, current to proposed |
| --- | --- | --- | --- | --- |
| 1 | A laptop showing a generic dashboard, on a case-study cover | Confirmed, fixed: a case-study cover shows a project-specific object or outcome, never a generic laptop or dashboard. `SKILL.md`; cover rule in `references/review-gates.md`; banned list in `references/visual-os/art-direction.md` | Must fix | Generic laptop and dashboard to one object or outcome specific to this project, reflecting the client's actual change |
| 2 | "Generic analytics dashboard" | Real interface over fake widgets; use the client's real screens, never invented ones; generated work is never presented as a real product screen. `references/visual-os/objects-and-components.md` | Must fix | Generic dashboard to, at most, one representative real product frame from the project |
| 3 | The laptop is the hero | A device is never the hero and never decoration; a generic laptop is on the avoid list. One dominant anchor, usually geometry. `references/visual-os/objects-and-components.md` | Must fix | Laptop as hero to one anchor, with any device below the hero metaphor |
| 4 | No stated claim | One claim, one tension, one proof, one outcome; the idea survives with the headline removed. `references/messaging.md` | Should fix | State what changed for the client's customer, then choose the object that carries it |

**What works.** Nothing in the description is reusable as it stands. The instinct to show the product is sound, if it becomes one real screen.

**Top three fixes, in order**

1. Remove the laptop, the desk and the generic dashboard.
2. Name the one thing this project changed, and pick the object or outcome from the client's own work that shows it. Which object is a choice for the case study in `wugweb-work`; I cannot name it without the project.
3. Build on one anchor with one real product frame at most, on the black canvas.

**Not judged**

- The image: colour, yellow share, text, craft, rights and legibility at final size. No score is given without the render.
- Anything about the client's brand or the case study's content: that stays with the case study in `wugweb-work`.
