Files read: SKILL.md, references/standing-rules.md, references/visual-os/art-direction.md, references/visual-os/objects-and-components.md, references/review-gates.md

## Response

No. The file is not cropped, by this skill or any other.

- **Media rule** (owner, `references/standing-rules.md`, "Media"): files are never cropped or re-encoded. This wins over any brand wording.
- **This skill** never makes, crops or re-encodes media (`SKILL.md`, "Never").
- **"Crop" in the guidelines** means how a subject is framed in a composition, never the cutting of a file (`references/visual-os/art-direction.md`, approved under question 12, 2026-11-17).

What the rules allow instead, as a proposal for whoever builds the piece:

| Current | Proposed | Rule |
| --- | --- | --- |
| Cut the screenshot file to a square | Keep the file as it is and show it inside the square at its original aspect ratio | Media may be shown at any size if the original aspect ratio is kept (2026-11-16) |
| A new square file | A clipping mask on the page, if the square must be filled | Clipping masks are allowed; resizing and masks are done on the page, never by making new files (confirmed 2026-11-16) |

Two checks on any mask:

1. It must not hide the part of the screen that proves the claim (confirmed 2026-11-16).
2. If the file ends up shown above its natural size, that is flagged, not banned.

Where it goes: the layout and the mask are `wugweb-kits` and `wugweb-work`. It is a client's screen, so which part is the proof is decided with its case study in `wugweb-work`, not here.

Not judged: I have not seen the screenshot or the square, so I cannot say whether a mask would cover the proof. Send the rendered result and I will run the Visual check.
